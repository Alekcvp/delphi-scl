# Simple Config Language (SCL)

SCL — это простой формат конфигурационных файлов, который сводит YAML к его базовой структуре, заимствуя практичные идеи из TOML. Базовые идеи формата - это простота и удобство, строгий парсинг и минимум неоднозначности.

## Основные принципы

*   Документ содержит **корневую таблицу** или **корневой массив**.
*   Корневая таблица/массив не могут быть строчными (`['a', 'b']` или `{a: 1; b: 2}`).
*   Обычные таблицы и массивы содержат **только одно значение в строке**.
*   Отступы из пробелов в начале строки определяют уровень вложенности. **Табуляторы не допускаются**.
*   После значения может идти комментарий, затем **обязательный перенос строки** или конец файла.

---

## Типы данных

### 1. Комментарии

Начинаются с символа `#`, действуют до конца строки. После значения элемента комментарий отделяется хотя бы одним пробелом.

```scl
# Это комментарий на всю строку
key: <value>  # Это комментарий после значения
```

### 2. Ключи и имена узлов

Допускаются латинские буквы, цифры и символ подчёркивания `_`.

```scl
simple_key: <value>
key_123: <value>
_private: <value>
```

### 3. Таблицы (словари)

Элементы имеют формат `key: <value>`. Вложенные таблицы и массивы, кроме строчных, должны начинаться с новой строки с увеличенным отступом.

```scl
appname: 'someapp'
checksum: 0x87fa4ed0

# Вложенные таблицы
servers:
  type: {http: true; ftp: false}
  http:
    port: 8080
    bind: 
      - '127.0.0.1'
      - '127.0.10.100'
```

**Строчная таблица** — записывается в одну строку в фигурных скобках `{}`, элементы разделяются `;`. Переносы строк в строчных таблицах запрещены, вложенные контейнеры запрещены.

```scl
point: {x: 10; y: 20; label: "origin"}
```

### 4. Массивы

Элементы имеют формат `- value`. Вложенность задаётся пробелами.

```scl
fruits:
  - 'apple'
  - 'banana'
  - 'cherry'
```

**Строчный массив** — записывается в одну строку в квадратных скобках `[]`, элементы разделяются `,`. Переносы строк и вложенные контейнеры запрещены.

```scl
tags: ['rust', 'config', 'parser']
```

#### Вложенные массивы и таблицы внутри массивов

Вложенные массивы и таблицы внутри обычных массивов могут размещаться двумя способами:

**На той же строке, что и `-`:**

```scl
items:
  - - 'subitem 1.1'
    - 'subitem 1.2'
    - 'subitem 1.3'
  - nested: 'table'
    next: 'item'
```

**С увеличенным отступом на следующей строке (как в таблицах):**

```scl
items:
  -
    - 'nested'
    - 'array'
    - 'items'
  - 
    nested: 'table'
    next: 'item'   
```

### 5. Целые числа

Не могут иметь ведущих нулей (кроме `0`). Для разделения групп цифр можно использовать символ `` ` ``.

```scl
answer: 42
negative: -17
zero: 0
big_number: 1`000`000
```

**Целые числа в других системах счисления** — могут иметь ведущие нули, разделитель групп запрещён.

```scl
binary: 0b1101
octal: 0o755
hex: 0x000FED0A
```

### 6. Вещественные числа

Без ведущих нулей в целой части. Разделитель групп `` ` `` разрешён, кроме части экспоненты.

```scl
pi: 3.14159
avogadro: 6.022e23
tiny: 1.5e-10
precise: 10`000.000`001
```

Специальные значения:

```scl
positive_inf: +inf
same_as_above: inf
negative_inf: -inf
not_a_number: nan
sign_ignored: -nan
```

### 7. Логический тип

```scl
enabled: true
alias: yes
verbose: false
quiet: no
```

### 8. Null

Символ `~` возвращает значение null, его интерпретация остаётся за приложением.

```scl
middle_name: ~
optional_field: ~
```

### 9. Массив байт (Hex)

Начинается с `%`, содержит **чётное** количество шестнадцатеричных цифр.

```scl
checksum: %A1B2C3D4
empty_bytes: %  # Пустой массив байт
```

### 10. Дата и время

Без миллисекунд. Символ `T` и пробел взаимозаменяемы. Секунды можно опускать, если они равны `0`.

**Полный формат (с временной зоной):**

```scl
created_at: 2004-10-23T13:32:20+03:00
updated_at: 2004-10-23 13:32:20-05:00
```

**Короткий формат (без временной зоны):**

```scl
timestamp: 2004-10-23 13:32
start_time: 2025-11-01T09:00  # секунды опущены, так как равны 0
```

**Только дата:**

```scl
birthday: 2025-11-01
```

**Только время:**

```scl
lunch_time: 12:00:00
alarm: 07:30      # секунды опущены
```

### 11. Строки

#### Обычная строка (`"`)

Поддерживает стандартные escape-последовательности (`\b`, `\e`, `\f`, `\n`, `\r`, `\t`), а так же коды символов (`\xHH`, `\uHHHH`, `\UHHHHHHHH`). Так же вместо `\"` можно использовать удвоенный символ кавычки `""`.

```scl
greeting: "Hello\nWorld!"
path: "C:\\Users\\name"
quote: "She said, \"Hi!\""
```

#### Символьная строка (`'`)

Воспринимается буквально, escape-последовательности не обрабатываются.

```scl
literal_path: 'C:\Users\name'
literal_quote: 'She said, "Hi!"'
```

Для включения символа одинарной кавычки внутрь строки допускается использование **удвоенных одинарных кавычек** (`''`), которые преобразуются в одну кавычку в результирующей строке.

```scl
example: 'It''s a beautiful day'   # → It's a beautiful day
nested: 'She said, ''Hello!'''     # → She said, 'Hello!'
```

#### Многострочная строка (`|`)

Сохраняет переносы строк. Первая строка содержимого должна иметь отступ не менее чем на 2 пробела больше отступа родительского ключа. Этот отступ первой строки считается общим для всего блока и удаляется из начала каждой строки. Всё, что находится в текстовом блоке после отступа - считается текстом.

```scl
description: | # comment
  This is the first line.
    This is the second line.
  And a third one.
  # Fourth line with a square
```

Результат:
```
This is the first line.
  This is the second line.
And a third one.
# Fourth line with a square
```

**Пустые строки в конце текстового блока.**

Парсер автоматически удаляет завершающие пустые строки в текстовых блоках. Для сохранения таких строк необходимо добавить в них пробелы, количество которых должно соответствовать текущему уровню отступа — это гарантирует, что пустая строка останется нетронутой. 

**Управление отступом.**

Если необходимо, чтобы первая строка начинались с пробелов, можно явно указать дополнительный отступ числом от 2 до 8 сразу после `|`. Число означает **сколько пробелов добавить к отступу ключа** при определении общей границы отбрасываемого блока.

```
<отступ ключа> + N пробелов = граница отбрасывания
```

Все пробелы правее этой границы сохраняются как содержимое. Строки, отступ которых меньше `<отступ ключа> + N`, завершают блок. Строки с отступом больше `<отступ ключа> + N` сохраняют разницу как ведущие пробелы.

```scl
# Ключ имеет отступ 0. |4 означает границу отбрасывания 0 + 4 = 4 пробела
root_text: |4
      Первые 4 пробела отброшены, два следуюших сохранены
        Эти 8 пробелов превратились в 4
    А эта строка не имеет отступа.
```

Результат:
```
  Первые 4 пробела отброшены, два следуюших сохранены
    Эти 8 пробелов превратились в 4
А эта строка не имеет отступа.
```

Пример с вложенным ключом:

```scl
config:
  # Ключ code имеет отступ 2. |4 означает границу 2 + 4 = 6 пробелов
  code: |4
      def hello():
          print("Hello, World!")
          return True
```

Отступ ключа `code`: 2 пробела. `|4` задаёт границу отбрасывания: 2 + 4 = 6 пробелов. Строки содержимого начинаются с 6 пробелов — они полностью отбрасываются. Содержимое с 10 пробелами превращается в 4 пробела.

Результат:
```
def hello():
    print("Hello, World!")
    return True
```

#### Свёрнутая строка (`>`)

Заменяет переносы строк на пробелы, объединяя текст в одну строку. Общий отступ отбрасывается по тем же правилам, что и для `|`, так же отбрасываются пробелы в конце каждой строки. Пустые строки внутри свёрнутой строки тоже отбрасываются, если не содержат отступа из пробелов.

```scl
help_text: >
  This long description

  will be folded into  
  a single line.


```

Результат: `This long description will be folded into a single line.`
Две пустые строки в конце блока были удалены из результата.

Если строка текста завершается символом `\`, то эта строка склеивается со следующей без пробела, сам данный символ `\` в результирующую строку не добавляется.

```scl
base64_key: >
  WGUobGAhK1omci5vfXJY\
  LjJRNC08a2UjajBAbUpD\
  IzxtOH4jbnBOTSxyO2hk 
```

Результат: `WGUobGAhK1omci5vfXJYLjJRNC08a2UjajBAbUpDIzxtOH4jbnBOTSxyO2hk`

**Управление отступом** и **обрезка пустых строк** работают аналогично многострочным строкам.

```scl
folded_indented: >4
      Эти слова останутся, а 4 пробела из 6 — нет.
    Эта строка станет продолжением предыдущей.
```

Результат: `  Эти слова останутся, а 4 пробела из 6 — нет. Эта строка станет продолжением предыдущей.`
